로컬 UI 검사 실행 방법

저장소 루트에서 공개 Firebase 개발 설정을 준비하고 구매자 개발 서버를 실행합니다. Playwright가 설치된 환경에서 아래 검사를 실행합니다. 테스트는 가상 인증·상품·주문 응답을 사용하며 실제 주문을 생성하지 않습니다.

npm run dev --workspace @bridge/customer
node tests/browser/commerce-motion.cjs

Playwright 모듈이 다른 경로에 있으면 PLAYWRIGHT_MODULE_PATH를 지정합니다. Windows 기본은 msedge 채널이며 로컬 기본 주소는 127.0.0.1:5173입니다.

관리자 최종 실제 화면

남은 목표와 기록 보존

입체 방, 여러 공간·패키지, 가상 센서, 담당자 권한 편집, 상세 검색·정교한 알림은 후속입니다. 기존 저장 기록 정리와 오래된 저장 통로 차단도 별도 작업으로 남았습니다.

기존 자료와 계정은 보존했습니다. 검증용으로 별도 시험 보관소 두 개를 만들었으며 운영 보관소와 구분됩니다. 실제 청구·배송·기기 연결은 없습니다.

뒤돌아보기: 확인된 사실은 세 화면 연결·두 주문·모션 배포입니다. 아직 모르는 것은 실제 장치 체감 품질입니다. 배포 성공만으로 전체 목표가 끝났다는 판단은 버렸고, 다음은 사용자 기기의 화면 평가입니다.

이 보고서는 작성 시점의 기록이며 자동 갱신되지 않습니다. 이전 보고서는 덮어쓰지 않았습니다.
