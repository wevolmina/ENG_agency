## 통합 시험 실행

MySQL 시험은 이름이 `_test`로 끝나는 전용 시험 DB에서만 실행됩니다. 운영 DB를 사용하지 마세요.

```powershell
$env:RUN_MYSQL_INTEGRATION='true'
node --env-file=apps/merchant/.env.local --import tsx --test tests/integration/mysql.test.ts
```

Firestore 규칙 시험은 실행 중인 에뮬레이터가 필요합니다.

```powershell
$env:FIRESTORE_EMULATOR_HOST='127.0.0.1:8080'
npx firebase-tools emulators:exec --project demo-payment-bridge --only firestore "npm run test:integration"
```

자동 시험은 화면 조작을 포함하지 않습니다. 최초 공개 전에 고객 화면의 동의 전 버튼 비활성화, 동의 후 주문, 새로고침 후 영수증 복원, 판매자 로그아웃 후 자료 제거도 브라우저에서 확인해야 합니다.

## 알려진 범위

- 실제 카드 결제·환불·정산 기능은 없습니다.
- 익명 고객 영수증은 동일 브라우저의 Firebase 인증 상태가 남아 있을 때 복원할 수 있습니다. 저장 데이터를 삭제하면 다른 기기에서 자동 복원되지 않습니다.
- 판매자 목록은 최근 100건만 제공합니다. 전체 조회용 페이지 나누기·CSV 내보내기는 없습니다.
- 이벤트 생성 후 MySQL 반영은 비동기이며 지연될 수 있습니다. 재전송 작업은 한 번에 최대 100건입니다.
- 앱 수준의 세밀한 악성 요청 속도 제한과 Firebase App Check는 이번 범위에 포함하지 않았습니다. 공개 데모 운영 전 사용량·접근 범위를 확인해야 합니다.
- 운영 서비스 계정·공유 비밀값·DB 비밀번호는 코드 및 압축 파일에 들어 있지 않습니다.
