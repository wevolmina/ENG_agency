# 최초 마스터 등록과 계정 승인

목표: 운영 DB에 직접 SQL을 입력하지 않고, 지정된 구글 계정이 최초 마스터로 등록한 뒤 화면에서 판매자·관리자 권한을 관리한다.

고객은 Firebase, 판매자는 기존 Vercel, 관리자는 별도 Cloudflare 사이트를 유지한다. 마스터 등록과 계정 승인은 Cloudflare 관리자 화면에서 진행한다.

## 1. 최초 한 번 Vercel 설정

기존 paybridge-mock 프로젝트의 Settings → Environment Variables에서 **Production**을 선택한다.

| 서버 전용 변수 | 입력할 값 |
| --- | --- |
| MASTER_SETUP_EMAIL | 마스터로 지정한 본인 구글 이메일 |
| MASTER_SETUP_MERCHANT_ID | 현재 상점 번호 studio-mina |
| MASTER_SETUP_PASSWORD | 본인이 정한 최초 설정 비밀번호. Secret으로 직접 입력 |
| FIREBASE_CLIENT_EMAIL | Firebase Admin SDK 서비스 계정 키의 client_email |
| FIREBASE_PRIVATE_KEY | 같은 키의 private_key. Secret으로 직접 입력 |

Firebase 두 항목은 운영 환경 변수 목록에서 미등록을 확인했다. 본인이 보관한 유효한 Firebase Admin SDK 서비스 계정 키에서 값을 직접 입력한다. 키 파일·내용을 채팅이나 저장소에 게시하지 않는다. 해당 서비스 계정은 Firebase Authentication 사용자 조회 권한이 필요하다. 키가 없다면 Firebase 프로젝트 설정 → 서비스 계정에서 인증 준비를 먼저 진행한다.

설정 비밀번호 값은 소스·예제 파일·문서·검증 기록에 넣지 않는다. Vercel의 서버 전용 비밀 설정에 저장한다. 환경 변수 저장 후 Production을 재배포해야 적용된다.

자동 배포는 앱 코드를 배포한다. 위 값이 없는 경우 최초 등록을 열지 않는다. 기존 Firebase 서버 인증·MySQL 연결·정확한 ADMIN_SITE_ORIGIN 설정도 필요하다.

## 2. 마스터 계정 등록

1. https://paybridge-admin.evolvix.workers.dev/ 에서 지정된 계정으로 **구글 로그인**한다.
2. 로그인 후 계정 승인 영역의 ‘최초 마스터 계정 등록’을 확인한다. 기존 관리자 권한이 없어도 이 영역을 볼 수 있다.
3. 최초 설정 비밀번호를 입력한다. 같은 계정으로 판매자 사이트도 이용하려면 해당 선택란을 체크한다. 판매자 권한은 선택 사항이다.
4. ‘마스터 등록’을 누른다. 서버가 두 개의 권한 관리용 표를 처음 한 번 준비하고 기존 권한 표에 역할을 등록한다. 사용자는 DB 도구를 열 필요가 없다.
5. 등록 완료 후 최초 등록을 잠근다. 그다음부터는 구글로 로그인한다. Vercel의 MASTER_SETUP_PASSWORD를 제거하고 재배포해도 등록된 마스터 권한은 유지된다.

서버는 서명·만료·사용 중지·인증 취소 상태를 확인한 Firebase 신원에서 이메일과 고유번호를 얻는다. 구글 로그인 여부, 토큰과 실제 계정의 이메일 인증 상태, 지정 이메일 일치, 최근 5분 이내의 로그인을 함께 확인한다. 화면에서 전달한 이메일·UID·상점 번호로 마스터를 지정하지 않는다.

하나의 프로젝트에서 최초 마스터와 상점 한 개를 연결한다. 설정 이메일이나 비밀번호를 바꿔도 이미 등록된 마스터를 다른 계정으로 자동 교체하지 않는다.

## 3. 판매자·관리자 승인

1. 승인이 필요한 사람이 판매자 또는 관리자 사이트에 먼저 로그인한다.
2. 로그인 후 표시되는 **내 계정 고유번호(UID)**를 본인이 확인한다.
3. 마스터가 관리자 사이트의 계정 승인 영역에 그 번호를 넣고 ‘계정 확인’을 누른다.
4. 표시된 계정 고유번호·이메일·이름을 소유자와 확인한다. 카카오·네이버는 이메일이나 이름이 제공되지 않을 수 있다.
5. 판매자 또는 관리자 역할을 선택하고 계정 확인 동의란을 체크한 뒤 승인한다.
6. 승인받은 사람은 해당 사이트에서 로그아웃하고 다시 로그인한다.

구글·카카오·네이버·기존 이메일 계정은 고유번호가 다를 수 있다. 같은 이메일이라는 이유로 자동 합치지 않는다. 등록된 계정만 승인할 수 있으며 사용 중지된 계정·비회원 계정은 거절한다. 다른 상점에 이미 연결된 역할을 이동시키지 않는다.

일반 관리자에게는 마스터의 계정 승인 기능을 제공하지 않는다. 지정된 구글 계정으로 등록한 마스터만 승인·해제할 수 있다.

## 4. 권한 해제와 기록

- 등록된 권한 목록에서 역할을 확인하고 ‘권한 해제’ → ‘해제 확인’을 누른다.
- 해당 역할의 다음 서버 요청부터 거절된다. 이미 표시된 화면은 다음 조회 때 정리된다.
- 마스터 자신의 관리자 권한은 이 화면에서 해제하지 못한다. 마스터의 판매자 역할은 별도로 해제할 수 있다.
- 권한을 다시 주려면 계정을 확인하고 해당 역할을 다시 승인한다.
- 최근 20개의 승인·해제 이력을 한국 시간으로 표시한다. 현재 상점의 최대 100개 권한을 표시하며, 고유번호로 개별 계정을 조회할 수 있다.

## 5. 보호와 오류 처리

- 설정 비밀번호는 단독 로그인 수단이 아니다. 지정된 본인 구글 계정의 최근 인증이 먼저 필요하다.
- 잘못된 설정 비밀번호를 5회 입력하면 15분 동안 등록을 잠근다. 횟수는 DB에 저장해 서버가 바뀌어도 유지한다.
- 최초 등록은 하나의 DB 행을 잠그고 처리한다. 동시 요청이나 재요청으로 두 마스터를 등록하지 않는다.
- 역할 변경은 마스터 권한을 다시 확인한 뒤 DB 트랜잭션으로 권한과 이력을 함께 저장한다. 다른 변경이 먼저 반영됐으면 재확인을 요청한다.
- 이 기능은 정확히 지정된 관리자 사이트 Origin과 Firebase 인증 토큰을 함께 요구한다. 비밀번호·인증 토큰을 URL에 넣거나 코드에서 로그로 출력하지 않는다.
- 결과를 확인하지 못했으면 비밀번호를 반복 입력하기 전에 ‘등록 상태 확인’을 누른다.
- 최근 로그인 확인 안내가 나오면 로그아웃하고 구글로 다시 로그인한다.
- 첫 등록에서 서버 오류가 나면 기존 DB 연결과 CREATE TABLE/SELECT/INSERT/UPDATE 권한을 운영자가 확인해야 한다. 이 앱은 기존 DB를 삭제하거나 새 DB로 전환하지 않는다.

## 이메일·고유번호 가림 표시

- 등록된 권한 목록에 이메일과 UID(계정 고유번호)를 각각 표시한다. 기본값은 `***`이며, 항목별 눈 버튼으로 표시·숨김을 전환한다.
- 승인 전 계정 확인, 본인 고유번호, 권한 해제 확인, 변경 이력에도 같은 가림 표시를 적용한다. 한 항목을 열어도 다른 항목은 계속 가려진다.
- 최초 설정 비밀번호·이메일 로그인 비밀번호·승인할 UID 입력란에는 입력한 값의 표시 여부를 바꾸는 눈 버튼을 추가했다. 비밀번호를 비우면 다시 숨김 상태가 된다.
- 화면의 긴 임의 문자열은 비밀번호가 아니라 Firebase 계정 고유번호다. 저장된 비밀번호·공급자 Client Secret·Firebase 서버 비밀키를 조회하거나 반환하는 기능은 제공하지 않는다.
- 등록 이메일은 서버가 마스터 권한과 상점 범위를 확인한 뒤 Firebase에서 현재 상점의 서로 다른 계정을 최대 100개까지 일괄 조회한다. 이메일만 추려 응답하며 전체 Firebase 사용자 기록·비밀번호 해시·토큰은 반환하지 않는다.
- 이메일 미제공, 삭제된 Firebase 계정, 프로필 조회 실패를 구분한다. 조회 지연은 5초 뒤 중단하고 기존 권한 목록은 유지한다.
- `***` 표시는 화면 노출을 줄이는 기능이다. 서버의 마스터 권한 검사와 별도로 동작한다.

시험용 계정으로 기본 숨김, 독립적인 눈 버튼, 입력값 초기화, 승인·해제, 접근성 이름에 원문이 나타나지 않음, 320/390/768/1440px 화면을 확인했다. 실제 운영 권한을 변경하지 않았다. 이번 변경의 배포 기록은 privacy-display-verification.json에 저장한다.

[이메일·고유번호 가림 표시 PR #6](https://github.com/wevolmina/paybridge-mock/pull/6)을 병합하고 고객·판매자·관리자 자동 배포 성공을 확인했다. 단위 검사 67개와 세 앱 빌드가 통과했다. 긴 고유번호를 펼친 상태의 모바일 화면도 점검했다. [검증 기록](privacy-display-verification.json)에 운영 소스와 배포 실행을 남겼다.
