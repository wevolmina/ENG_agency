# 페이브릿지 UI·UX와 상태 모션 개선

기준일: 2026-10-25 한국 시간. 비교한 구현 기준은 `898e905`이며, `feed-mina/ME`의 계획과 `wevolmina/paybridge-mock`의 실제 코드를 대조했다.

## 확인한 차이

모션 전체가 누락된 상태는 아니었다. 구매자 모의 결제 완료, 판매자 새 주문, 침실 조명·시점 전환은 이미 구현되어 있었다. 다만 관리자 패키지 영역은 그림 없이 긴 목록이었고, 관리자에게 일반 주문 알림도 표시되어 역할별 알림 계획과 차이가 있었다.

|구매자 선택|기존 선택 테두리|구성 추가 180ms, 선택 그림의 작은 확대, 체험 카드 호버|

## 모션 원칙

최초 조회와 같은 자료의 재조회에는 거래 모션을 재생하지 않는다. 구매자는 서버의 `MOCK_APPROVED` 응답을 받은 뒤 완료를 표시하며, 영수증 복원 시에는 완료 모션을 반복하지 않는다. 판매자는 기존에 보지 못한 결제 번호를 기준으로 새 주문을 알리고, 관리자는 새로 확인한 패키지 변경 이력 번호를 기준으로 안내한다.

기기의 움직임 줄이기 설정에서는 이동·확대·전환 애니메이션을 끈다. 선택 여부와 공개 상태는 글자·테두리·배경으로 계속 알 수 있다. 일반 갱신에는 숫자 롤링이나 반복 모션을 넣지 않았다.

## 검증과 범위

실행 명령과 상세 결과는 [검증 기록](verification.md)에 정리한다.

이번 변경은 화면·모션·알림 표현에 한정한다. 권한·DB 구조·결제 API를 변경하지 않았고 운영 주문 생성이나 패키지 공개 상태 변경을 수행하지 않았다. 승인·정산·취소·환불의 새 업무 상태를 구현한 것은 아니다. 서버 검색, 권한 편집, 다른 공간의 3D 구현 등 기존 전체 계획의 남은 항목을 완료로 표시하지 않는다.

고객 앱은 Firebase Hosting, 직원 앱은 Vercel로 각각 배포해야 한다. 소스 변경이나 PR 생성만으로 양쪽 운영 배포 완료를 의미하지 않는다. 배포용 공개 Firebase 설정은 기존 환경에서 주입해야 하며, 로컬 시험 설정을 사용하면 안 된다.

## 주요 코드

- `apps/merchant/app/StaffDashboard.tsx`: 공개 필터, 저장 대상, 역할별 알림, 초점 복귀, 변경 이력, 공간 그림.
- `apps/merchant/app/dashboard-ux.css`: 관리자·판매자 배치와 짧은 사건 모션, 작은 화면 대응, 움직임 줄이기.
- `apps/customer/src/CartStore.tsx`, `cart.css`: 공간 바로가기와 선택 구성 피드백.
- `tests/browser/dashboard-motion-ux.cjs`, `store-motion-ux.cjs`: 시험용 인증·API 응답을 사용하는 회귀 검증.
