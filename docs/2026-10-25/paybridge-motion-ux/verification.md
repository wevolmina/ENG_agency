## 실제 시험한 동작

- 최초·동일 응답에서는 새 주문·패키지 변경 알림 없음.
- 판매자에게 새 결제 1건을 전달하면 새 행과 매출을 한 번 강조. 안내가 사라진 뒤 같은 응답을 받아도 다시 알리지 않음.
- 관리자의 일반 새 주문은 조용히 반영. 새 패키지 변경 이력만 안내하고, 동일 변경은 반복하지 않음.
- 전체·공개·중지 필터와 공개 수 표시, 변경 이력의 패키지 이름·전후 상태 표시.
- 저장 결과가 충돌(409)이면 성공으로 표시하지 않고 패키지 영역에 이유 표시.
- 공개 필터에서 저장한 카드가 제외되면 선택된 필터로 키보드 초점 복귀.
- 구매자 공간 바로가기 3개, 선택 없음 안내, 선택 3개 합계 277,000원.
- 구성 변경 시 기존 동의 해제.
- 응답 유실 후 재확인은 동일 요청 본문을 사용. 완료 시 영수증 3항목과 제목 초점 확인.
- 영수증 복원 시 완료 모션 반복 없음.
- 움직임 줄이기에서 패키지 확대와 구성 진입 모션 없음.

시험 중 판매자 안내와 매출 영역에 같은 React key를 쓰면 안내 DOM이 남는 문제가 발견되어, 키에 영역별 접두사를 붙여 해결했다. 안내가 사라지는 검사까지 최종 통과했다.

## 재실행

의존성을 설치하고 각 앱의 공개 Firebase 설정을 준비한 뒤, 서로 다른 터미널에서 앱을 실행한다.

```bash
node --import tsx --test tests/*.test.ts
npm run build
npm run dev --workspace @bridge/merchant
npm run dev --workspace @bridge/customer -- --port 5188
```

별도 터미널에서 Playwright가 사용 가능한 환경으로 브라우저 검사를 실행한다. 인증과 업무 API는 시험 코드에서 대체하며 실제 주문·패키지 상태를 쓰지 않는다.

```bash
node tests/browser/dashboard-motion-ux.cjs
node tests/browser/store-motion-ux.cjs
```

기본 직원 주소는 `http://127.0.0.1:3000`, 구매자 주소는 `http://127.0.0.1:5188`이다. `STAFF_BASE_URL`, `UI_BASE_URL`로 바꿀 수 있다. 브라우저는 기본 Edge이며 `PLAYWRIGHT_CHANNEL`, 또는 `BROWSER_EXECUTABLE_PATH`와 선택 사항 `BROWSER_ARGS_JSON`으로 바꿀 수 있다. `UI_EVIDENCE_DIR`은 캡처·JSON 저장 위치다. `QA_FONT_CSS`는 선택 사항인 로컬 캡처용 폰트 CSS 경로다.

이번 환경에서는 Linux Chromium과 Node.js 24로 실행했다. 저장소 권장 Node.js 22에서의 재실행은 이번 별도 확인하지 않았다. 일반 `npm test` 실행기는 환경의 임시 소켓 제한으로 시작하지 못하여, 같은 24개 테스트를 `node --import tsx --test`로 실행했다.

구매자 빌드에는 기존 Three.js 관련 500kB 초과 청크 경고가 남아 있다. 새 제품 의존성은 추가하지 않았다. 로컬 시험용 공개 Firebase 값은 Git에서 제외했고 배포하지 않았다.
