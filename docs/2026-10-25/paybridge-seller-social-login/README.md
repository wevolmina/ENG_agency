# 판매자 구글·카카오·네이버 간편로그인

기준: 2026-10-25 한국 시간. 판매자 URL은 https://paybridge-mock.vercel.app/ 그대로 사용한다. 관리자 앱은 https://paybridge-admin.evolvix.workers.dev/ 의 별도 Cloudflare 배포를 유지한다.

## 변경한 동작

- 판매자 로그인 화면에 구글·카카오·네이버 버튼을 추가하고 기존 이메일/비밀번호 로그인을 유지했다.
- 고객·관리자와 같은 로그인 서버와 공급자 앱을 사용한다. 공급자 콜백 주소는 기존 Vercel 주소를 유지한다. 새 키를 고객·판매자·관리자 화면에 넣지 않는다.
- 판매자 사이트의 정확한 운영 주소를 로그인 결과 전달 대상으로 허용한다. 임의의 미리보기 주소나 외부 사이트는 허용하지 않는다.
- 판매자와 서버가 같은 주소이면 브라우저가 설정 조회 GET에 Origin 헤더를 생략한다. 이 경우 서버의 정식 주소와 Sec-Fetch-Site: same-origin을 함께 확인해 준비 상태만 반환한다. 외부 Origin이 명시되면 이 예외를 적용하지 않는다.
- 로그인 중 이메일 입력·다른 로그인 시도를 잠그고, 취소·오류·로그아웃 이후 다시 사용할 수 있게 한다.
- 간편로그인 성공만으로 판매자나 관리자 권한을 발급하지 않는다. 매출 API가 검증된 Firebase 사용자 고유번호(UID)로 DB의 활성 merchant 역할과 상점 번호를 확인한다.

## 사용할 계정

구글·카카오·네이버 계정의 UID는 기존 이메일 계정과 다를 수 있다. 이메일이 같아도 기존 판매자 권한이나 주문을 자동 연결하지 않는다. 실제 사용할 계정으로 로그인한 뒤 소유자·UID·상점 번호를 확인하여 권한 등록 여부를 점검한다. 이번 변경에서는 운영 DB의 역할을 생성하거나 변경하지 않았다.

## 공급자 설정

기존 [공통 로그인 설정 가이드](../paybridge-social-login/README.md)의 서버 변수와 콜백을 그대로 사용한다.

| 공급자 | 로그인 결과를 받는 주소 |
| --- | --- |
| 카카오 | https://paybridge-mock.vercel.app/api/auth/social/callback/kakao |
| 네이버 | https://paybridge-mock.vercel.app/api/auth/social/callback/naver |

Vercel Production에 등록한 환경 변수는 재배포 후 적용한다. 준비 상태가 false인 공급자는 연결 준비 중으로 표시한다. 개발자 앱 등록·검수와 실제 계정 로그인 성공은 버튼 구현·활성화와 구분한다.

## 검증 범위

- Node.js 22 단위 검사 44개 통과. 판매자 주소 허용, Origin 없는 동일 출처 조회, 외부·미리보기 주소 거절, 두 공급자의 판매자 콜백과 역할 미부여를 확인했다.
- 고객·판매자·관리자 빌드 통과.
- 시험용 인증·업무 응답을 사용하는 브라우저 검사 통과: 판매자 카카오 로그인 후 권한 없음 차단, 네이버 로그인 후 허용된 매출 화면, 요청의 Firebase 인증 토큰, 잘못된 팝업 메시지 거절, 로그인 중 입력 잠금, 로그아웃·이메일 복귀.
- 고객 비회원 주문 보호와 기존 고객·관리자 동작 회귀 검사 통과. 두 직원 사이트의 로그인·로그아웃 분리도 확인했다.
- 화면 너비 320/390/768/1440px 가로 넘침 없음, 브라우저 실행 오류 없음.
- 이 시험은 실제 공급자 계정 로그인·운영 주문 생성·운영 DB 권한 변경을 수행하지 않았다.
