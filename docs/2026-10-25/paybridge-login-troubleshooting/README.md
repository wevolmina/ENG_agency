# 계정 승인 표시와 간편로그인 실패 점검

기준일: 2026-10-25 한국 시간.

## 확인한 사실

- 일반 계정에도 StaffAccess의 제목 ‘계정 승인’이 공통 표시되고 있었다. 승인 입력과 등록 목록은 isMaster/canSetup으로 구분했지만 제목·메뉴가 혼동을 주었다.
- 서버는 최초 지정된 구글 계정 확인 후 마스터 UID를 한 번 고정한다. 이후 마스터 UID, 온라인 구글 신원, 활성 관리자 소속을 함께 검사한다. 일반 관리자도 다른 계정을 조회·승인할 수 없다.
- 판매자 구글 로그인에서 ‘이 로그인 방법은 연결 준비 중입니다’ 오류를 운영 브라우저에서 재현했다. 기존 안내는 auth/unauthorized-domain과 auth/operation-not-allowed 등을 같은 문구로 처리해 정확한 원인을 구분할 수 없었다.
- 세 운영 앱의 공개 Firebase 설정은 같은 프로젝트·인증 도메인·앱을 가리킨다. 실제 키·비밀번호·토큰은 보고서에 기록하지 않는다.
- 로그인 버튼 활성화는 서버 환경 변수의 존재만 확인한 결과다. 카카오·네이버 인증 완료나 개발자 콘솔 설정의 유효성을 증명하지 않는다.

## 수정 내용

일반 계정의 제목은 ‘이용 권한 안내’, 메뉴는 ‘내 계정’으로 표시한다. 서버에서 마스터 또는 최초 등록 대상임이 확인된 계정에만 승인 제목과 관리 메뉴를 표시한다. 서버의 기존 권한 경계는 유지한다.

로그인 오류에는 허용 목록의 고정 진단 코드만 표시한다. 구글의 허용 도메인·제공업체 비활성·프로젝트 불일치를 구분하고, 카카오·네이버는 토큰 교환 / 계정 정보 조회 / Firebase 토큰 발급을 구분한다. 제공업체 원문, 앱 키, 시크릿, 인증 코드, 개인 토큰은 표시하지 않는다.

판매자는 간편로그인으로 Firebase 계정이 만들어져도 판매자 역할이 자동 승인되지 않는다. 로그인 성공 뒤 ‘내 계정’의 고유번호를 마스터에게 전달하고, 마스터가 판매자 역할을 승인한 뒤 다시 로그인하는 구조다. 별도 신청 대기함은 구현되어 있지 않다.

## 설정 확인 위치

- Firebase Authentication: Google 활성화와 실제 승인된 도메인 목록을 확인해야 한다. 저장소 firebase.json에 적는 것만으로 운영 설정이 바뀌지는 않는다. 고객 Hosting 배포는 Auth 설정을 덮어쓰지 않는다.
- 카카오 Redirect URI: `https://paybridge-mock.vercel.app/api/auth/social/callback/kakao`
- 네이버 Callback URL: `https://paybridge-mock.vercel.app/api/auth/social/callback/naver`
- 세 사이트는 같은 Vercel 로그인 서버를 사용하므로 고객·관리자 주소를 위 콜백 대신 입력하지 않는다.

실제 제공업체 인증 및 설정 변경 완료 여부는 별도 검증 기록에 남긴다. 시험 자료를 사용하는 검사와 실제 계정 로그인은 구분한다.

## 운영 확인 결과와 남은 단계

[PR #8](https://github.com/wevolmina/paybridge-mock/pull/8)을 병합했고 세 사이트 자동 배포가 모두 성공했다. 단위 검사 71개와 브라우저 검사 3종이 통과했다.

Firebase Console에서 Google은 활성화되어 있으나 실제 승인된 도메인은 고객의 두 Firebase 주소와 관리자 Cloudflare 주소만 있었다. 판매자 `paybridge-mock.vercel.app`이 누락되어 있으며 새 오류 안내에서도 `auth/unauthorized-domain`을 재현했다. 판매자 도메인은 입력만 준비했으며 아직 저장하지 않았다.

카카오는 제공업체 로그인 화면과 실제 계정 인증을 통과하여 Paybridge에 회원번호를 제공하는 동의 단계까지 확인했다. 동의 제출·콜백·Firebase 연결은 아직 검증하지 않았다. 네이버 실제 인증 역시 미검증이다. 카카오·네이버 실패 원인이 모두 해결되었다고 볼 수 없다.

승인 대기: 판매자 주소의 Firebase 허용 목록 추가, 카카오 회원번호의 Paybridge 제공 동의. 승인 뒤 실제 콜백과 로그인·판매자 역할을 이어서 검증해야 한다. 실제 계정 이메일·비밀번호·인증 토큰은 기록하지 않는다.

## 사용자 승인 후 진행

판매자 주소를 Firebase 승인된 도메인에 저장했고 목록에서 재확인했다. 판매자 구글 로그인은 기존 도메인 오류를 통과해 실제 계정 선택과 기기 본인 인증 단계까지 진행했다. 로그인 최종 완료 여부는 별도 확인한다.

승인받은 카카오 회원번호 제공 동의를 제출했으나 Vercel 서버의 토큰 교환에서 `SOCIAL_TOKEN_EXCHANGE_FAILED`로 거절되었다. 카카오 로그인이 완료된 것은 아니다. 고정 허용 목록에 있는 공식 KOE 오류만 추가 구분하며, 제공업체 원문·시크릿·인증 코드는 출력하지 않는다. 키·시크릿을 붙여 넣을 때 생긴 앞뒤 공백도 제거한다.

네이버 버튼은 사용자 요청대로 공통 CSS에서 `display:none`으로 숨긴다. 고객·판매자·관리자 모두 적용하며 고객 로그인 버튼 배치는 두 열로 조정한다. 접근 가능한 버튼 목록에서도 제외되는지 검사했다. 숨김은 화면 정책이며 네이버 개발자 설정이나 서버 연결을 삭제하지 않는다.
