# 페이브릿지 UI/UX 문제 보고

기준일: 2026-10-25 한국 시간. 분석 기준: 운영 화면과 `3b1c1c81290a7cc7d9d5c206aed92c8564f3ef99` 소스. 사용자 요청에 따라 기존 분석을 기록한다.

## 핵심 판단

기능을 추가할 때 화면 전체의 정보 우선순위와 역할별 사용 흐름을 다시 설계하지 않았다. 기능 수에 비해 시각적 완성도와 사용 편의가 낮아 보이는 주된 원인으로 판단한다. 기능 검사 통과는 미적 완성도나 실제 사용성 검증을 의미하지 않는다.

## 확인한 문제

|문제|확인 근거|사용자에게 미치는 영향|
|---|---|---|
|고객의 공간 소개보다 로그인이 먼저 노출|안내 → 큰 로그인 영역 → 구매 단계 → 공간 소개 순서. 분석 시 데스크톱 핵심 제목 시작 약 682px|로그인이 선택 사항인데 필수처럼 느껴지고 공간 체험의 가치가 늦게 보임|
|판매자·관리자의 시각적 구분 부족|주소는 분리되어 있지만 같은 StaffDashboard의 틀·사이드바·로그인 배치 사용|두 서비스의 역할 차이를 화면에서 이해하기 어려움|
|긴 로그인과 고른 시각적 무게|분석 환경 로그인 카드 높이 약 831px, 하단 버튼이 첫 화면 아래. 연한 배경·테두리·회색 설명 반복|시선의 우선순위가 불분명하고 여백에 비해 사용 흐름은 답답함|
|개발·운영 설명이 전면에 노출|DB 연동, 서버 역할 확인, 조회 주기 등의 반복 문구|상품과 업무보다 내부 처리 방식을 먼저 이해해야 함|
|계정이 권한별 행으로 나뉨|같은 UID의 판매자·관리자 권한이 별도 행. 이메일·UID는 기본 가림|동일 인물의 권한을 한 번에 파악하기 어려움|
|관리자 기능이 긴 한 화면에 누적|계정 승인, 패키지, 매출, 주문, 변경 이력이 한 흐름에 배치|현재 업무와 무관한 영역을 지나쳐야 함|
|개별 모션과 전체 흐름의 차이|선택·주문·조명 피드백은 있으나 공간 탐색이 화면 중심이 아님|애니메이션을 추가해도 첫인상과 탐색 흐름 문제는 남음|

위 픽셀 수치는 분석 당시 브라우저 크기에서의 관찰이며 모든 기기의 고정값이 아니다. 로그인 이후 관리자 구조는 최신 소스를 근거로 분석했다. 실제 사용자 대상 사용성 시험은 수행하지 않았다.

## 수정 계획과 완료 기준

1. 고객: 첫 화면을 침실 장면과 체험 버튼 중심으로 재배치하고 선택적 간편로그인은 접어서 제공한다.
2. 판매자: 별도 로그인 화면, 매출 개요·주문·내 계정을 구분한다. 누적 집계의 기간을 오인시키지 않는다.
3. 관리자: 패키지·계정 권한·주문·변경 이력을 메뉴별로 구분한다.
4. 계정: 같은 UID의 역할을 한 계정 카드에 묶는다. 이메일·UID·입력 비밀번호 가림 및 눈 버튼을 유지한다.
5. 표현: 역할별 강조색, 글자 크기, 간격, 카드와 버튼을 통일하고 상태 변화 모션과 움직임 줄이기를 유지한다.
6. 검증: 세 앱 빌드, 인증·역할·결제 회귀 검사, 모바일·키보드·화면 검토, 실제 자동 배포 결과를 별도 기록한다.

결제·로그인·권한 부여의 서버 정책과 DB는 이번 UI 개선의 변경 대상이 아니다. 신청 대기함이나 새 승인 절차를 구현한 것으로 표시하지 않는다. 관리자 Cloudflare, 판매자 기존 Vercel, 고객 기존 Firebase 주소를 유지한다.

작업 상태와 배포 결과는 같은 폴더 README 및 verification.json에 기록한다. 이 문제 보고서 자체는 수정·배포 완료 증거가 아니다.
